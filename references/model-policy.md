# Модель и расход: проверяемый выбор

Проверено 2026-09-29: [модели Codex](https://learn.chatgpt.com/docs/models), [кредиты Codex](https://learn.chatgpt.com/docs/pricing), [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol). Это датированная политика, а доступность проверяется в среде получателя.

Для всех маршрутов этой сборки целевая модель — **GPT-6.1 Sol**, точный идентификатор `gpt-6.1-sol`. Официальная формулировка — близкое к Astra качество при меньшей цене; не утверждать, что Sol умнее Astra или всегда использует меньше токенов. GPT-6 Sol (`gpt-6-sol`) — отдельная предыдущая модель, GPT-5.6 Sol — другое поколение. Не подменять их молча. Названия SO/Soul без номера неоднозначны: проверить каталог и контекст.

| Задача | Предпочтение пользователя | Когда повысить глубину/модель |
|---|---|---|
| Узкая ясная правка, извлечение, форматирование | GPT-6.1 Sol / low, с проверяемым результатом | Неясность или ошибка: GPT-6.1 Sol / medium, затем high |
| Обычный кодинг, дизайн, исследование, документы | GPT-6.1 Sol / medium | Несколько зависимых решений, сложная отладка: high |
| Архитектура, безопасность, система навыков, трудная реализация | GPT-6.1 Sol / high | После целевой проверки повысить effort этой же модели; другую модель предложить только с конкретной причиной и явным выбором пользователя |
| Самая сложная работа с высокой ценой ошибки | GPT-6.1 Sol / high; xhigh/max только по конкретной необходимости | Не переключаться на Astra автоматически; при недостаточном качестве объяснить конкретный пробел |

Medium/high здесь — выбранная рабочая политика пользователя, а не универсальный официальный default. В локальном каталоге 2026-09-29 GPT-6.1 Sol default=low; API-документация указывает medium. Выбирать только поддерживаемые уровни клиента. Для GPT-6.1 Sol API не поддерживает none/minimal. xhigh/max нужны по наблюдаемой сложности, ultra не включать без разрешённого делегирования. Fast не включать автоматически: он увеличивает расход.

## Перед рекомендацией

1. Проверить доступность точного идентификатора через интерфейс/каталог клиента; в Codex CLI — `codex debug models`. Сохранять только slug, display_name, поддерживаемые усилия и дату; не публиковать полный каталог с системными промптами, ключи или конфигурацию аккаунта.
2. Если GPT-6.1 Sol недоступна, сообщить об этом один раз. Не подменять её самостоятельно. Предложить доступный резерв; смена модели требует явного выбора пользователя. Независимую работу можно продолжить на текущей модели с обозначением ограничения. Не загружать другую модель и не создавать задачи для обхода доступа.
3. Навык рекомендует маршрут, но не переключает исполняющийся ответ. Использовать только подтверждаемый механизм среды в авторизованном объёме. При отсутствии переключателя назвать рекомендацию в приложении; не заявлять, что модель изменена. Новая конфигурация действует для новых сессий, текущая может сохранять собственный выбор.
4. Оценивать качество на одинаковых заданиях, критериях и effort. Astra, Luna и прежняя Sol — только явно выбранные пользователем альтернативы; не выбирать их автоматически по типу задачи и не объявлять хуже по одному испытанию. Повторное сравнение оправдано провалом, изменением модели или значимым новым типом задачи.
5. Разделять количество токенов, тариф, оценку кредитов и реальные лимиты подписки. Проверять input/cached/output usage, время и результат; не обещать процент экономии по одному прогону. Reasoning output — часть output, повторно не прибавлять без подтверждения схемы клиента.

## Standard: датированные тарифы кредитов

За миллион входных / кэшированных входных / выходных токенов: GPT-6.1 Sol — **50 / 2.5 / 250**, GPT-6 Sol — **50 / 5 / 250**, GPT-6 Astra — **250 / 25 / 1250**. При одинаковых категориях токенов GPT-6.1 Sol дешевле Astra в 5 раз на input/output и в 10 раз на cached input. Это не означает меньше фактических токенов или столько же экономии лимитов подписки. Fast, план и тип использования имеют отдельные множители; тарифы API не выдавать за кредиты Codex. При изменении тарифа обновить эту датированную таблицу, не переписывая исторические результаты.
