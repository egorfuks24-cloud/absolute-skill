# Проверка безопасности создаваемого приложения

В этом профиле пользователь включил проверку приложения в завершение его разработки. При проектировании учитывать данные, доверенные границы и доступы. Когда основной код готов, до сдачи выполнить соразмерный обзор безопасности и исправить подтверждённые проблемы в разрешённой области. Не спрашивать «хочешь проверку?»; не превращать каждую косметическую правку в полный повторный аудит.

Выбрать один основной доступный процесс: Codex Security security-scan для приложения, security-diff-scan для ограниченного изменения; при отсутствии — vibe-audit плюс ручная проверка кода по рискам ниже. Прочитать выбранный SKILL.md. Если специализированного инструмента нет, прямо назвать проведённый ручной обзор и его границы; не имитировать запуск. SkillSpector/absolute-skill-safety проверяет пакет навыков и не заменяет этот этап.

Проверять применимые поверхности с доказательствами:
- секреты в клиенте, истории изменённых файлов и конфигурации; не выводить значения секретов в отчёт;
- аутентификация, завершение сессии и серверная авторизация на конкретном объекте/пользователе;
- валидация внешних данных, инъекции, вывод HTML и команды, загрузки файлов и исходящие URL;
- хранение/передача чувствительных данных, журналы, доступы к БД и хранилищу;
- зависимости и настройки сборки/развёртывания, публичные административные функции, ограничения запросов для злоупотребляемых операций.

Для каждой применимой области: проверенный путь/настройка/тест, наблюдение, результат или непроверенное. Для находки: место, предпосылки, реальный ущерб, уровень с обоснованием, исправление и повторная проверка. Ответы «не применимо» обосновывать архитектурой. Не придумывать уязвимости для количества; автоматический сигнал сначала проверить.

Обзор исходников и локальные проверки входят в работу. Активные атаки на чужую или рабочую среду, доступ к приватным данным, установка зависимостей сканера, отправка кода внешнему сервису и разрушительные тесты не разрешаются этим этапом автоматически. Использовать локальные изолированные примеры и имеющиеся инструменты.

Записать результаты в VERIFICATION с областью/версией и способом. Если существенная поверхность не проверена, указать пробел; если осталась подтверждённая серьёзная уязвимость — не объявлять готовность к публикации. Само приложение можно передать с точным статусом ограничений. Отсутствие находок не доказывает абсолютную безопасность.
