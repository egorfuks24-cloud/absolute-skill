# Разработка концепций и сюжет опыта

## Различать концепцию и оформление
Для нового продукта после исследования показать 2–3 альтернативы с разными основными действиями/последствиями, а не одинаковый сайт в разных цветах. Смысл, польза и ясность важнее декоративной необычности. Не требовать необычность там, где стандартная форма лучше задаче.

В каждой концепции:
- конкретный человек/контекст и решаемая трудность;
- основной цикл: вход → действие → последствие → обратная связь → осмысленный следующий шаг;
- отличительная механика и сравнение с изученными аналогами, включая совпадения;
- первая минута/первый законченный сценарий: последовательность 3–5 состояний с реальным контентом;
- роль композиции, типографики, изображения и движения в этой механике;
- источник приёмов, что адаптируется, что исключается;
- нагрузка/сложность/контент/зависимости, риски и проверка ценности;
- причина отказаться от этой концепции, даже если она визуально эффектная.

Для сайта сюжет — последовательность действий и изменения понимания пользователя, не обязательная художественная история и не рекламный слоган. Для торговли/инструмента приоритет — успешная задача; для обучения — понятное упражнение и перенос знания. Не добавлять игровые награды, 3D и анимации по умолчанию.

## Синтез вложенных материалов
Выбирать навыки/источники по конкретной роли: UI для действия, иллюстрация для смысла, движение для изменения состояния, разработка для надёжности, безопасность для реальных границ. Не применять всю коллекцию ради её размера. Разрешённые источники определяют визуальное основание, но допускают новую обоснованную комбинацию и собственные предметные иллюстрации в выбранной концепции. Запрет привычного модельного дизайна не запрещает рассуждать и разрабатывать оригинальную механику. Нельзя произвольно придумать внешность и легализовать её ссылкой.

Рассмотреть минимум один подход без тяжёлых эффектов и сопоставить с более выразительным, если это реально полезно. Пользователю показывать конкретные последствия и пробы, а не просить самому собрать концепцию. После ответов на бриф самостоятельно исследовать и подготовить материалы. Пользователь выбирает направление/существенные компромиссы один раз; уже разрешённые шаги выполнять дальше.

## Пробы
До выбора продукта — короткая концепция и карта сценария; после разрешения брифа допустимы изолированные пробы в .absolute/options. Для визуального выбора показать первый законченный цикл, а не только обложку: вход, ключевое действие, результат. Обычно два основных варианта, третий только при содержательной альтернативе. На wide/narrow показать тот же сценарий. Проверить качество исходных активов и необходимость текста до фиксации эталона. Запись «approved» и выбор тестового агента не заменяют реального пользователя.

Сохранять CONCEPTS.md и concept-plan.json по шаблону. На стадии explored проверить scripts/concept_check.py; на selected добавить подлинную запись выбора. Перед реализацией нового продукта проверить selected и существующий design_check ready. Точечная правка готового продукта не требует задним числом выдумывать новое исследование; сохранять имеющиеся решения.

## Достаточность и объём
Для концептуальной проработки результат — понятные альтернативы и решение, а не количество документов. Обычно 2 сильных концепции достаточно; не добавлять третью по квоте. Общие источники и ограничения описать один раз, не дублировать их в каждом файле. Concept-plan нужен только для новой продуктовой концепции, которую проверяем/передаём в реализацию; для краткого обсуждения достаточно CONCEPTS.md. В сценарной проверке, где concept-plan явно нужен, JSON и человекочитаемый текст должны быть краткими и согласованными. Не создавать визуальный контракт до визуального выбора.

Для учебного сценария варианты ответа должны быть правдоподобными и сопоставимыми: явно нелепый отвлекающий ответ не проверяет понимание. Указать, как принимается и оценивается каждый ответ. Свободное объяснение ученика без модели/инструктора не выдавать за автоматически проверяемое; отличать сбор ответа, заранее заданные варианты и человеческую оценку. Перенос на новую ситуацию показать отдельно; предполагаемые секунды не выдавать за фактическую длительность.

Для нового визуального направления применять [design-synthesis.md](design-synthesis.md): роль источников, авторская адаптация и разделение сравнения концепций/оформления.
